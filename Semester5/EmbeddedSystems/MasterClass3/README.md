# Мастер-класс 3. Вариант 1: «Змейка» на FreeRTOS

Готовый проект находится в `SDK_Snake`. Платформа: SDK-1.1M с **STM32F407VGT6**, OLED 128×64 и матричной клавиатурой 4×3. Для STM32F427 нужны другая конфигурация микроконтроллера, startup и linker script.

Основа: https://github.com/lmtspbru/SDK-1.1M, commit `bd8cba8f4bd5fc2d1460e6ad4da7b7dd13d9e14d`. Проект, HAL, CMSIS и FreeRTOS взяты из `SDK_FreeRTOS`; OLED, шрифты и I²C из `SDK_OLED`. Сканирование клавиатуры повторяет схему строк и столбцов из `SDK_Keyboard`, но проверяет ошибки чтения. Исходный репозиторий сохранён в `upstream`.

## Запуск в STM32CubeIDE

1. `File → Import → General → Existing Projects into Workspace`.
2. Выбрать папку `SDK_Snake`, импортировать проект `SDK_Snake`.
3. Выбрать конфигурацию `Debug`, выполнить `Project → Build Project`.
4. Подключить стенд через USB DBG. Создать конфигурацию отладки для доступного адаптера: встроенный FTDI стенда использует OpenOCD и файл `SDK11M.cfg`; внешний ST-Link требует своего подключения и настройки.
5. Загрузить прошивку и запустить выполнение. Игра начинается на паузе; нажать `5`, чтобы запустить движение.

Проект редактируется непосредственно в C. `SDK_FreeRTOS_original.ioc` в корне оставлен только для справки: он описывает исходный пример с миганием светодиодов. **Не генерировать из него код поверх `SDK_Snake`: это заменит задачи игры.** Готовому проекту генерация CubeMX не нужна.

## Управление

Ориентация матрицы: ROW1 — верхняя строка, ROW4 — нижняя; столбцы слева направо. Как в стандартной цифровой клавиатуре:

```text
1       2 ↑     3
4 ←     5 pause 6 →
7       8 ↓     9
* reset 0       #
```

После включения и перезапуска игра стоит на паузе: нажать `5` для старта.

Каждое действие выполняется по новому нажатию; удерживать направление не требуется. Перед следующим нажатием отпустить кнопку. Нажатие нескольких кнопок одновременно игнорируется. `5` переключает паузу, `*` начинает новую игру, в том числе после проигрыша или победы. Если маркировка клавиш на конкретном стенде отличается, использовать указанные позиции матрицы.

Поле 30×12 клеток, размер клетки 4×4 пикселя. Еда появляется только во внутренних клетках, с отступом в одну клетку от каждого края; углы исключены. Еда изображается крестиком, голова — квадратом с тёмным центром. За еду начисляется одно очко и добавляется один сегмент. Каждые три очка интервал движения уменьшается на 15 мс: от 240 до 90 мс. Столкновение со стеной или телом завершает игру; заполнение всех внутренних клеток означает победу. В верхней строке выводятся счёт и состояние `SNAKE`, `PAUSE`, `LOST *` или `WIN *`.

## Организация FreeRTOS

| Задача | Приоритет CMSIS | Стек, слов | Назначение |
|---|---|---:|---|
| Input | AboveNormal | 256 | Опрос клавиатуры с периодом 10 мс, три одинаковых отсчёта для подавления дребезга, события новых нажатий |
| Game | Normal | 256 | Обработка команд и движение по времени FreeRTOS; единственный владелец состояния игры |
| Display | BelowNormal | 512 | Ожидание снимка состояния и отрисовка OLED |

В этой реализации CMSIS v1 размер стека передаётся в `xTaskCreate` в словах `StackType_t` (4 байта).

- `commands`: очередь на 8 команд, каждый элемент — `uint8_t`. При переполнении новое нажатие отбрасывается, ввод не блокирует задачу.
- `frames`: очередь длины 1 со снимком `SnakeGame` по значению. `xQueueOverwrite` оставляет последнее состояние, поэтому медленный дисплей не задерживает игру.
- `i2c_mutex`: мьютекс с наследованием приоритета для общего I²C1. Защищает полный скан клавиатуры и отправку каждой страницы OLED. Во время ожидания следующего периода мьютекс освобождён.
- I²C1: PB8/SCL, PB9/SDA, 100 кГц; адрес OLED для HAL — `0x78`, PCA9538 клавиатуры — `0xE2` (уже сдвинуты влево).
- FreeRTOS использует SysTick 1 кГц; HAL использует TIM1, как в исходном примере. Системная частота — HSI 16 МГц.
- `HAL_Delay` используется только для начальной настройки OLED до запуска планировщика. Задачи используют блокировки очереди и `vTaskDelayUntil`.

Отрисовка принадлежит одной задаче, поэтому отдельный мьютекс для буфера OLED не нужен. Два мьютекса одновременно не захватываются. За один шаг разрешён только один поворот, разворот на 180° запрещён. Перезапуск очищает оставшиеся команды.

## Сборка без IDE

Из корня мастер-класса можно использовать `lab.sh`, как в МК2:

```sh
./lab.sh build   # собрать
./lab.sh flash   # собрать, прошить, проверить и запустить
./lab.sh clean   # удалить результаты сборки
./lab.sh debug   # запустить OpenOCD, остановить процессор
./lab.sh gdb     # подключиться к OpenOCD из второго терминала
```

Скрипт находит инструменты в PATH или установленном STM32CubeIDE. При необходимости задать `CUBEIDE_PLUGINS`, `OPENOCD_BIN`, `OPENOCD_SCRIPTS`, `JOBS`. Прошивка использует адаптер FTDI стенда и `SDK_Snake/SDK11M.cfg`.

На этом Mac Makefile автоматически находит компилятор установленного STM32CubeIDE:

```sh
make -C SDK_Snake -j4
```

Для другой установки:

```sh
make -C SDK_Snake TOOLCHAIN=/path/to/bin/arm-none-eabi- -j4
```

Результат: `SDK_Snake/build/SDK_Snake.elf`, `.bin`, `.hex`. Начальный адрес Flash для бинарного файла — `0x08000000`.

## Проверки

Прошивка успешно собрана и слинкована ARM GCC 13.3.1: text 23020 байт, data 112 байт, bss 20192 байта. Предупреждения относятся к неиспользуемым параметрам исходных HAL/CMSIS/syscalls и RWX-сегменту исходного linker script; ошибок сборки нет.

Логика игры проверена отдельно на компьютере с AddressSanitizer и UndefinedBehaviorSanitizer:

```sh
clang -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined \
  -ISDK_Snake/Core/Inc tests/test_snake.c SDK_Snake/Core/Src/snake.c \
  -o /tmp/mc3_test_snake
/tmp/mc3_test_snake
```

Проверены: старт, размещение еды вне тела, запрет разворота, один поворот за шаг, пауза, рост и счёт, столкновения, вход в освобождаемую клетку хвоста, перезапуск, ограничение скорости, победа при заполнении поля.

На физическом стенде выполнение пока не проверено. После загрузки проверить дисплей, все четыре направления, паузу/продолжение и перезапуск; затем рост после еды и проигрыш от стены. Драйвер OLED сохранён из примера: он не сообщает задаче ошибки передачи кадра. При отсутствии OLED на старте выполнение останавливается в `Error_Handler`; ошибки чтения клавиатуры не трактуются как нажатия.

## Основные файлы

- `SDK_Snake/Core/Src/snake.c` — игровая логика без зависимости от HAL и ОС.
- `SDK_Snake/Core/Src/freertos.c` — задачи, очереди, мьютекс и отрисовка.
- `SDK_Snake/Core/Src/keyboard.c` — чтение клавиатуры через PCA9538.
- `REPORT.md` — описание для отчёта и защиты.
- `tests/test_snake.c` — проверки игровой логики.

Лицензионные уведомления исходных библиотек сохранены в их файлах.

Звук: пример SDK_Buzzer, TIM2_CH1 / PA5, отдельная задача Sound и очередь sounds (8 событий). Сигналы старта, паузы, перезапуска, еды, проигрыша и победы; задержки нот через vTaskDelay. Один общий i2c_mutex используется Input и Display.
