# УИР3 — исследование СМО и СеМО

Подготовлена часть 1 для СИСТЕМЫ_1 из УИР2, вариант 32/32/30:
расчёты, независимый событийный симулятор, 76 текстовых моделей GPSS World,
графики, таблицы и отчёт `report.pdf` с исходником `report.typ`.

**Числа в отчёте получены Python-симулятором, а не GPSS World.**
Нативная трансляция и выполнение GPSS не проверены: GPSS World здесь не установлен.
Для полного выполнения требования о работе в GPSS нужны нативные прогоны.

**Часть 2 ожидает отдельный вариант А/В** (А=1…52, В=1…10).
Исходный вариант УИР2 не определяет его. Сетевые модели и результаты без
этой пары не создавались. Условия обеих частей сохранены в `task.pdf`.

## Воспроизвести расчёты

Python 3.12+, Typst для сборки отчёта:

```sh
cd Semester5/Modeling/Research3
uv venv --python 3.12
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python solve.py
typst compile report.typ report.pdf
```

В среде подготовки использовался уже установленный интерпретатор
`../Research2/.venv/bin/python`, без изменения соседних работ.

`solve.py` выполняет самопроверки и все эксперименты. Основные:
8 повторов по 100000 поступлений после 20000 прогревочных;
seeds 2026000…2026007. ДИ 95% — по независимым повторам с квантилем Стьюдента.
Для начального режима — 40 запусков из пустой системы на каждый префикс.
Расчёт занимает несколько минут, точное время зависит от компьютера.

Отдельная быстрая самопроверка:

```sh
.venv/bin/python simulation.py
```

Проверяются FIFO, отказы, одновременное завершение и поступление,
интеграл очереди, окно прогрева, точное решение M/M/2/7 и моменты H2.
В полном запуске дополнительно проверяются результаты УИР2 и M/G/1.

Ёмкость `capacity` — только места ожидания, не общая вместимость.
Пустая `capacity` в CSV и `null` в JSON — бесконечная очередь.
`rho` — предложенная нагрузка b/(ka); `utilization` — измеренная занятость приборов.
В группе `servers_fixed_work` нагрузка изменяется с k, а `reference_rho` задана для k=2.
`lost` и `elapsed` в сводной таблице — средние по повторам, отдельные целые
числа отказов находятся в `replicates.csv`.
Суффикс `_ci` обозначает половину доверительного интервала; СКО времён
и неопределённость оценки среднего — разные величины.

Трасса из УИР1 повторяется циклически, с сохранением порядка. В Python каждый
повтор начинается со случайной позиции, GPSS начинает с первой строки.
`numbers_example.txt` сохранён как пример и не подменяет трассу из 300 значений.

## Проверка в GPSS World

1. Открыть текстовый `models/S000.gps` как модель GPSS World. Файл примера
   `input/smo_GGKE_original.gps` — другой, исходный бинарный документ.
2. Выполнить `Command / Create Simulation`, устранить возможные ошибки
   трансляции и сохранить журнал. Подготовленные исходники ещё не проходили
   через нативный компилятор, поэтому здесь не заявлена их проверенная исполняемость.
3. В модели уже присутствует `START 120000`: создаётся ровно 120000 заявок,
   затем принятые досчитываются до конца. Оба выхода, обслуженный и отказ,
   уменьшают счётчик завершения на 1. Времена `Wait` и `Stay` не цензурируются
   ранней остановкой.
4. В REPORT взять `Wait` / `Stay` MEAN и STD.DEV., `Buffer` AVE.CONT.,
   `Pool` UTIL. Вероятность потери: Savevalue `Lost` / `Arrived`.
   В `S000` ожидаются примерно: Pотк=0,60011; W=31,6867 с; T=41,6867 с;
   Lq=6,33559; U=0,999725. Конкретный случайный прогон отличается от расчёта.
5. Для моделей трассы рабочим каталогом сделать `models`, чтобы открылся
   `trace.txt`. Проверить нулевые коды матрицы `ErrorCodes`, отсутствие ошибок
   чтения и фактический период 300 чисел. Нельзя использовать прогон с ошибкой ввода.
6. Для исследования начального режима делать отдельные `CLEAR` и `START N`
   для N=10,50,100,200,300,…; одновременно устанавливать лимит GENERATE равным N.
   Без изменения лимита короткий START остановится до полного досчёта когорты.
7. Для прогретых результатов создать отдельную копию модели: убрать ограничение
   числа GENERATE и строку START, выполнить `START 20000`, затем `RESET` и
   `START 100000` без CLEAR. Записать разности накопительных Savevalue `Lost`
   и `Arrived` до и после второго прогона. RESET сбрасывает статистику,
   но не состояние очереди; Savevalue следует учитывать отдельно.
   Это наблюдение по завершениям и стандартная статистика GPSS; оно не задаёт
   точно ту же приёмную когорту, что Python. При необходимости точного
   совпадения окна добавить отметку прогретых заявок и раздельные таблицы.
8. Повторить с независимыми начальными состояниями генераторов (`RMULT`),
   оценить ДИ по прогонам, сопоставить с `comparison_research2.csv`.
   Python seeds не являются значениями генераторов GPSS с тем же потоком чисел.

В исходниках агрегированы одинаковые приборы через STORAGE. Такая модель
подходит для общесистемных W, T, потерь и средней занятости; она не измеряет
раздельную загрузку П1/П2 при предпочтении 0,65/0,35.

Синтаксис сверялся с авторским
[GPSS World Reference Manual, главы 6–8](https://athena.ecs.csus.edu/~mitchell/csc148/gpssW/Reference%20Manual/reference_manual.htm),
копия California State University, Sacramento. Это справочная проверка,
не замена запуска программы.
